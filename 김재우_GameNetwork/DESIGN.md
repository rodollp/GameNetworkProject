# NGO 코인 게임 — 설계 문서

## 1. 프로젝트 개요

Unity 6와 Netcode for GameObjects(NGO)를 활용하여 Host와 Client가 함께 플레이할 수 있는 코인 획득 게임을 구현했습니다.

플레이어 이동, 코인 획득, 점수 동기화를 주요 기능으로 구성했습니다.

특히 코인 획득과 점수 변경은 서버에서 처리하여 클라이언트가 임의로 점수를 변경하지 못하도록 설계했습니다.

## 2. 주요 클래스와 역할

| 클래스 | 역할 |
|---|---|
| `NetworkLancher` | Host 및 Client 시작, 접속 중복 실행 방지 |
| `NetworkCharacterPlayer` | 플레이어 입력 및 CharacterController 이동 |
| `NetworkScorePlayer` | 플레이어 점수 관리, 서버 RPC 요청 |
| `NetworkCoin` | 코인 충돌 감지, 서버 검증 및 코인 제거 |

각 클래스가 담당하는 기능을 분리하여 플레이어 이동과 코인 획득, 점수 관리를 구분했습니다.

## 3. 네트워크 구조

NGO의 Host/Client 구조를 사용했습니다.

- Host는 서버와 클라이언트 역할을 함께 수행합니다.
- Client는 서버에 접속하여 자신의 플레이어를 조작합니다.
- 서버는 코인 획득 요청을 검증하고 점수를 변경합니다.
- `NetworkVariable`을 이용하여 점수 변경 결과를 동기화합니다.

### 서버에서 코인을 처리하는 이유

클라이언트에서 직접 점수를 변경하면 잘못된 요청이나 중복 요청으로 점수가 증가할 수 있습니다.

이를 방지하기 위해 클라이언트는 코인 획득을 요청하고, 서버가 조건을 확인한 후 결과를 결정하도록 했습니다.

## 4. 플레이어 이동 설계

플레이어 이동에는 `CharacterController`를 사용했습니다.

`NetworkCharacterPlayer`는 `NetworkBehaviour`를 상속받으며, `IsOwner`를 통해 자신이 소유한 플레이어에 대해서만 입력을 활성화합니다.

입력에는 Unity Input System을 사용했습니다.

동일한 입력 액션을 여러 플레이어가 공유하면서 발생했던 입력 문제를 해결하기 위해 `InputAction.Clone()`을 사용하여 플레이어별 입력을 분리했습니다.

플레이어의 이동 결과는 네트워크 동기화 컴포넌트를 통해 상대 실행 화면에도 전달하도록 구성했습니다.

## 5. 코인 획득 설계

### 코인 획득 처리 순서

```text
플레이어가 코인에 접촉
        ↓
NetworkCoin.OnTriggerEnter()
        ↓
소유 플레이어인지 확인
        ↓
NetworkScorePlayer.RequestCollectCoin(coinId)
        ↓
RequestCollectCoinRpc(coinId)
        ↓
서버에서 코인 ID 조회
        ↓
NetworkCoin.TryCollect(player)
        ↓
거리 및 중복 획득 검사
        ↓
점수 증가
        ↓
코인 Despawn
```

### 서버 검증 항목

**1. 코인 존재 여부**

전달받은 코인 ID가 실제로 생성된 네트워크 오브젝트인지 확인합니다.

`SpawnManager.SpawnedObjects.TryGetValue()`를 이용해 해당 오브젝트를 조회합니다.

**2. 코인 컴포넌트 확인**

조회한 오브젝트가 `NetworkCoin` 컴포넌트를 가지고 있는지 확인합니다.

**3. 거리 검사**

서버에서 플레이어와 코인의 거리를 계산합니다.

설정된 획득 거리인 `2f` 이내에 있을 때만 획득을 허용합니다.

**4. 중복 획득 방지**

`isCollected` 변수를 사용하여 이미 획득 처리된 코인이 다시 점수를 지급하지 않도록 했습니다.

**5. 코인 제거**

정상적으로 획득한 코인은 `NetworkObject.Despawn()`으로 제거합니다.

## 6. 점수 동기화 설계

플레이어 점수는 다음과 같이 `NetworkVariable<int>`로 관리합니다.

```csharp
public NetworkVariable<int> Score = new NetworkVariable<int>(0);
```

점수 증가 요청은 RPC를 통해 서버에 전달합니다.

서버에서 점수를 변경하면 변경된 값이 네트워크를 통해 동기화됩니다.

점수 UI는 해당 플레이어의 점수 데이터를 참조하도록 구성했습니다.

## 7. 잘못된 요청 처리

클라이언트가 존재하지 않는 코인 ID를 전달하는 상황을 시험하기 위해 `ulong.MaxValue`를 이용한 잘못된 ID 요청 기능을 구현했습니다.

서버는 전달받은 ID로 코인을 찾을 수 없으면 요청을 거절합니다.

또한 이미 획득된 코인이나 획득 거리를 벗어난 요청도 처리하지 않도록 설계했습니다.

## 8. 구현 과정에서 발생한 문제와 해결

### Host와 Client 입력 문제

**문제:** Client를 실행했을 때 Host의 입력이 정상적으로 동작하지 않는 문제가 발생했습니다.

**원인 및 해결:** 플레이어들이 입력 액션을 공유하는 문제를 확인하고 `InputAction.Clone()`을 이용하여 각 플레이어가 독립적인 입력 액션을 사용하도록 변경했습니다.

### 점수 로그 중복 출력

**문제:** Host에서 점수 증가 로그가 두 번 출력되는 현상이 발생했습니다.

**해결:** 플레이어 프리팹이 중복 배치된 부분을 확인하고 수정했습니다.

### 코인 제거 경고

**문제:** 씬에 배치된 NetworkObject를 제거하는 과정에서 관련 경고가 발생했습니다.

**대응:** 코인 오브젝트의 생성 방식과 `Despawn()` 처리 방식을 확인했습니다.

## 9. 설계상 제한 사항

- 동일 PC의 Host/Client 실행 환경을 기준으로 구현했습니다.
- 코인 획득은 서버에서 검증하지만 모든 종류의 비정상 클라이언트 동작을 방어하는 것은 아닙니다.
- 외부 네트워크 접속 및 대규모 다중 접속 환경은 구현 범위에 포함하지 않았습니다.
- 플레이어 이동 동기화와 종료·재접속 동작은 최종 실행 환경에서 확인해야 합니다.

## 10. 수업 코드 활용 및 직접 구현 내용

NGO의 `NetworkBehaviour`, `NetworkObject`, `NetworkVariable`, RPC 등은 수업에서 학습한 내용을 기반으로 활용했습니다.

직접 구현하거나 수정한 주요 내용은 다음과 같습니다.

- 플레이어 소유권에 따른 입력 처리
- `InputAction.Clone()`을 이용한 입력 분리
- 코인 ID를 이용한 서버 획득 요청
- 서버의 코인 존재 여부 및 거리 검증
- 중복 획득 방지
- 코인 획득과 점수 증가 처리

세부적인 시험 과정과 결과는 `TEST_REPORT.md`에 기록했습니다.
