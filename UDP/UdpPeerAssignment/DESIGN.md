# UDP 피어 위치 동기화 설계

## 실행
.NET 8 이상 콘솔 프로젝트의 `Program.cs`를 사용한다. 같은 프로그램을 두 번 실행한다.

- A: `dotnet run -- A 127.0.0.1 9000 127.0.0.1 9001`
- B: `dotnet run -- B 127.0.0.1 9001 127.0.0.1 9000`

인자 순서: `피어ID 내IP 내포트 상대IP 상대포트`. 두 프로그램은 서로 다른 로컬 포트를 사용한다.

## 데이터와 규약
UTF-8 텍스트 UDP 데이터그램 하나에 `피어ID|순서번호|X|Y`를 담는다. 예: `A|1|3|5`.
- 피어 ID: `A` 또는 `B` (이 실습은 두 피어만 지원)
- 순서 번호: 1부터 증가하는 양의 64비트 정수; 새 위치 메시지마다 증가
- X/Y: 부호 있는 32비트 정수
- 좌표 변경 시에만 새 위치 메시지를 만든다. `burst`는 시험용으로 매번 X를 바꾼다.
- `old`, `duplicate`는 당시 전송했던 메시지 문자열을 수정하지 않고 다시 보낸다.

## 송수신 및 상태
`SendPositionAsync`는 내 좌표와 순서 번호로 메시지를 생성하고 `SendAsync`로 전송한다. `ReceiveMessagesAsync`는 별도의 비동기 작업으로 계속 수신한다. 메인 입력 루프는 수신 대기 때문에 막히지 않는다. 송신과 수신이 공유하는 상태는 `lock`으로 보호한다.

수신 시 예상 상대 IP/포트, 피어 ID, 필드 수, 숫자 변환을 검사한다. 피어별 최신 상태는 `Dictionary<string, Position>`에 보관한다. 이전에 반영한 순서 번호보다 큰 메시지만 적용한다. 작은/같은 번호는 무시하고 기록한다. 잘못된 메시지는 프로그램을 종료시키지 않고 통계에 반영한다.

## 시험 명령
- `3 5`: 자신의 좌표 변경 및 송신
- `show`: 내 위치와 상대의 최신 위치 및 순서 번호 표시
- `stats`: 누적 송신완료/송신오류/수신/위치반영/중복·오래됨/잘못된 메시지 표시
- `old`: 최초 송신 위치 메시지를 원래 번호/좌표 그대로 재전송
- `duplicate`: 마지막 송신 위치 메시지를 원래 번호/좌표 그대로 재전송
- `invalid`: 빈 데이터그램 및 잘못된 형식 메시지 2개 전송
- `burst 100 10`: 10ms 간격 100개, `burst 1000 0`: 지연 없이 1000개. 각 메시지는 새 좌표와 증가한 번호 사용
- `exit`: 종료

## 한계와 측정 주의
`SendAsync` 완료는 상대의 수신 확인이 아니다. `stats`의 수신 수는 해당 프로세스가 실제로 받은 UDP 데이터그램 수이며, 유실이 확정된 수가 아니다. 송신 측 burst 시간은 송신 루프 소요 시간이다. 상대의 수신은 이후에도 계속될 수 있다. 각 시험 전 프로그램을 재시작하여 누적 통계를 초기화하고, 수신이 안정될 때까지 기다린 뒤 양쪽의 `stats`와 `show`를 기록한다. 이 예제는 자동 재전송, 순서 번호 순환 및 재시작 상태 복구를 지원하지 않는다.
